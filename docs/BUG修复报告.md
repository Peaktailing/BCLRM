## 二、高危缺陷（7 条，已全部修复）

### H1 未生效工单被计入用量统计
- **现象**：教师提交含管控化学品的工单（此时已写入领用量）→ 管理员**驳回**。该明细永远不会被归还，`用量 = 领用量 − 归还量` 被永久计为全额。
- **影响**：「学期用量」「数据看板」以及**采购的人均用量测算**全部偏高，且误差随时间单调累积、无法事后修正。
- **根因**：`business/usage_service.py` 遍历工单时没有任何状态过滤。
- **修复**：新增 `USAGE_ORDER_STATUSES`（借用中 / 部分归还 / 已归还）与 `is_effective_order()`，`collect()`、`usage_by_user()`、`usage_by_month()`、`list_semesters()` 全部过滤。
- **验证**：`已归还 → True`、`待审批 → False`。

### H2 采购量填 0 仍会凭空造出库存
- **现象**：把某明细「采购量」改为 0（语义=库存够、不买了）→ 汇总 → 下单 → 到货 →「按采购单入库」，系统反而按**需求量**生成一瓶，且明细已回填瓶号，**不可重来**。
- **根因**：`float(item.purchase_quantity or item.demand_quantity or 0)` —— `0.0` 是 falsy，触发回退。
- **修复**：改为显式判空 `if item.purchase_quantity is not None`；采购量为 0 的明细直接跳过并提示「采购量为 0，不予入库」。

### H3 危化品采购审批可被绕过
- **现象**：含危化品采购单获批 → 取消 → 退回草稿（`approval_status` 仍为「已批准」）→ 把采购量 100 改成 10000 → 重新提交 → **直接进入汇总与跟踪，全程未再审批**。
- **根因**：`cancel_plan` 只改 `status`，未清审批痕迹。
- **修复**：取消时一并清空 `approval_status / approver / approval_time / approval_remark`。

### H4 覆盖生成静默清空人工修改
- **现象**：人工改过量后，为改「预计人数」再次点「生成 / 覆盖采购单」（单号不变）→ 人工修改全部丢失。
- **根因**：覆盖分支 `delete_by_plan` 重建全部明细。
- **修复**：覆盖前记录 `is_manual` 的明细，按「实验 + 试剂」匹配继承其采购量 / 供应商 / 备注；本次预估不再出现的旧明细以 `is_manual=1` 单独保留；落库后按实际明细重算条数与总量。

### H5 领用扣库存与工单落库不在同一事务
- **现象**：清单 3 瓶，前 2 瓶领用成功（已扣库存、已置「已借出」），第 3 瓶建单阶段异常回滚 → **已领用的 2 瓶没有任何工单记录**，永远无法归还，用量统计丢失。
- **修复**：把 `reagent_borrow` 循环移入 `with db.transaction()`，与工单创建同一事务；全失败时回滚并返回原有失败原因。

### H6 已过期瓶仍出现在「只显示可借」的领用清单
- **现象**：已过期但仍有剩余量的瓶能加入领用清单，提交时才报错「已过期，禁止借出」；而同一瓶在「需求调配」里被正确排除 —— 同状态两页面两结论。
- **根因**：`expiry_service` 只写 `expired_flag`，未同步 `borrowable_check`，而查询按 `borrowable_check` 过滤。
- **修复**：`check_and_update` 置「已过期」时同步 `borrowable_check=0`；恢复正常且有剩余量、未报废时恢复为 1。

### H7 批量入库放宽校验导致管控与过期双双失效
- **现象**：无 CAS、未建档的试剂经「按采购单入库」进入系统后 → ① 管控目录按 CAS 匹配失效，**危化品可无审批领用**；② 无档案 + **未写生产日期** → 过期判定恒返回「正常」，**这批瓶永不过期**。
- **修复**：
  - 领用与入库的管控判定增加**按名称兜底匹配**管控名录（`controlled_list` 含名称/别名）；
  - 批量入库新增**生产日期（必填）**与存储位置输入，并从化学品档案回填试剂类型与 CAS；
  - 汇总/统计侧统一排除报废瓶。

| M1 | 正在借用的瓶可被流转管理权，产生「借用人 + 管理人」双重归属 | `transfer` 前置校验可借状态（非「归还回转」场景），借出中拒绝并提示先归还 |
| M2 | 调配单不锁瓶，同一瓶可被两个需求、甚至与工单同时占用 | 新增 `_reserved_bottle_numbers()`：已被「待处理」调配单预占的瓶不再参与分配；`handle` 借出前复校验可借状态 |
| M3 | 调配 `qty` 为部分量、借出却是整瓶转移，账面对不上 | UI 与文档明确「调配 = 整瓶保管权转移」，`qty` 仅作需求分配参考；智能计算的存量口径与分组口径统一 |
| M4 | `manager_stock_qty` 与分组用了两套管理人归一口径，可能显示「你的存量 0g」 | `_stock()` 统一用 `resolve_manager()` 归一后再比较 |
| M5 | 采购入库把采购量同时当规格与剩余量，且不写生产日期 | 新增生产日期输入、试剂类型回填；文档说明「采购量 = 本次到货总量」 |
| M6 | `borrowable_flag` 与 `borrowable_check` 双事实源，注释互相矛盾 | 在 `ReagentBottleService.update / update_by_field` 统一派生：写 flag 自动同步 check（唯一收口点） |
| M7 | 报废/恢复与过期无互斥；报废瓶余量仍计入存量 | 确认报废同步 `borrowable_check=0`；恢复时若仍为「已过期」则不回到可借池；采购存量与看板统计排除报废瓶 |
| M8 | 汇总用「需求量」算 `final_purchase`，实际按下单量 | 汇总新增 `total_purchase`，`final_purchase` 按采购量计算；UI 增列「总采购量」并加说明 |
| M9 | 汇总按试剂名合并、CAS 取首条，错录会被吞掉 | 合并键改为「试剂名 + CAS」，同名多 CAS 时输出告警 |
| M10 | 审批按瓶号回写，把该瓶**全部历史**领用流水标记为已审批 | 改为按「领用人 + 领用时间」精确定位本工单产生的流水 |
| M11 | 归还比例拖到 0% 会**隐式**判为空瓶且不可逆 | 空瓶改为界面**显式勾选**「空瓶（用完，移入待报废）」，比例 0% 不再自动判空瓶 |

## 四、低危缺陷（已修复）

- `list_open_orders` 在 `user_name` 为空时鉴权失效 → 改为非管理员一律按本人过滤（空值返回空列表）。
- 负数归还量被静默丢弃 → 改为记录失败原因并提示。
- 看板统计「分类之和 ≠ 总数」（过期瓶不属于任何分类、报废瓶被计入耗尽）→ 分类互斥且穷尽，新增「已过期 / 已报废」计数。
- 采购汇总的 CAS 冲突、缺学年预定单由静默忽略改为明确提示。

## 六、遗留风险（需业务侧决策，代码已具备支撑）

1. **CAS / 化学品档案缺失（887 瓶、143 个名称）**
   当前管控判定已增加「按名称兜底」，可在档案缺失时仍识别危化品；但**过期判定与类型统计仍无法生效**。
   建议：以「化学品信息表」为准做一次批量补档（试剂名 → CAS / 类型 / 有效期），补档后过期预警才会完整生效。
2. **调配 qty 与整瓶流转的语义**：当前按整瓶流转保管权，若需要「分装后按量流转」，需引入分装/多瓶拆分能力。
3. **调配单与工单共用同一把「瓶占用锁」**：本轮已实现「待处理调配单预占」，但工单侧仍未纳入统一锁；极端并发下仍需进一步统一。
4. **`login-frontend` 历史目录**：早期提交中曾存在的前端 mock 文件已从分支历史清除，无需处理。
