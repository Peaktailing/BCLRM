## 二、数据库迁移说明

启动应用时 `db.init_tables()` / `_run_migrations()` 会自动执行以下变更：

1. `reagent_bottle`、`borrow_record`、`return_record`、`borrow_order_item`、`purchase_plan_item`、`purchase_order` 增加 `unit TEXT DEFAULT 'g'`。
2. `reagent_bottle` 继续保留/补充 `expiry_date` 字段；新入库记录会按未启封有效期计算并写入。
3. 旧结构 `purchase_plan` 升级时不再 `DROP TABLE`，而是重命名为 `purchase_plan_legacy_<时间戳>` / `purchase_plan_item_legacy_<时间戳>` 保留数据。
4. `chemical_info` 重建后重新创建 `updated_at` 触发器。
5. schema 迁移异常不再静默忽略，会抛出并中止启动，避免半迁移状态。

> 建议升级前备份 `db/main.db`、`db/main.db-wal`、`db/main.db-shm` 以及 `attachments/` 目录。WAL 模式下只复制 `.db` 可能丢失最近事务。

## 三、行为变化（升级需知）

### 1. 页面权限
- `views/2_试剂入库.py`、`views/7_化学品信息管理.py` 现在要求管理员及以上；普通用户/教师仅可查看库存和查询。
- 服务层对入库、化学品维护、采购生成/修改/提交/审批/入库/状态流转增加角色校验（无登录上下文时放行，兼容脚本/测试）。

### 2. 首次登录
- 完全未设置密码的历史账户仍可用默认初始密码首次登录，但登录后会被强制跳转到改密表单，改密前不能进入业务页面。
- 系统设置页新增用户改为生成一次性随机初始密码，不再统一使用 `123456`。

### 3. 过期状态
- 缺少生产日期或无法解析日期的瓶子标记为“待确认”，不会直接阻断借出（避免历史数据全部不可用），但会在看板/处置页提示补录。
- 借出、智能调配前会按日期实时计算过期状态，不再只信 `expired_flag`。

### 4. 单位
- 库存、领用、归还、工单明细、采购明细、采购单均增加 `unit`，默认 `g`。
- 统计与采购汇总按 `试剂名 + CAS + 单位` 分组，g 与 mL 不再直接相加。
- 入库页新增计量单位选择（g/kg/mg/mL/L）。

### 5. 安全配置
- `.streamlit/config.toml`：`enableCORS=true`、`enableXsrfProtection=true`、`showErrorDetails=false`。
- 若通过反向代理/内网访问，请确认代理层已配置 HTTPS、访问控制和限流。

### 6. 路径
- `config/settings.py` 的数据库、日志、附件目录改为基于项目根目录的绝对路径，避免从其他工作目录启动时产生“分裂库”。

## 四、测试与验证

执行：

```bash
./.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

结果：**186 个测试全部通过**。

新增/加强的回归覆盖：

- 无 CAS 的管控试剂必须进入审批；
- 含管控化学品的采购单未审批时禁止提交；
- 多次部分归还不能把库存越还越多；

- `sync_all` 在“正常→已过期”转换时同步清零 `borrowable_check`；

- 数据库连接测试增加真实断言；
- 附件索引库测试改用临时库。

另用符号表检查确认项目内已无未定义名称；`import services`、`scripts.import_from_docs`、`scripts.import_teachers`、`tests.test_transaction` 均可独立导入。

## 五、已知限制与后续建议

1. **智能调配仍未携带单位**：需求单/调配单明细没有 `unit`，管理员之间流转整瓶时按瓶内单位处理；若需要跨单位需求换算，需继续扩展 `reagent_demand_item` / `allocation_order_item`。
2. **按月用量仍按单一标量汇总**：`usage_by_month` 未按单位拆分；混合单位场景建议以“课程-实验-试剂”明细为准。
3. **跨进程并发**：借还已使用条件更新，采购入库使用逐项事务+条件回填；但整体仍建议单写进程部署，SQLite 不适合多实例高频写入。
4. **归档冷库**：`archive_cold.db` 仍只有批次元数据表，历史数据搬运尚未实现。
5. **WAL 目录**：`db_wal/` 目录仍未真正参与 SQLite 写入；备份时请包含 `-wal`/`-shm` 文件或先执行 checkpoint。
6. **旧脚本**：`scripts/import_data.py` 已修正人员表列名，但其他工作表若仍使用旧模板，需要按当前 schema 继续核对。
7. **空密码历史账户**：强制改密已实现；建议上线后由管理员批量通知/重置长期未登录账户。

## 六、回滚建议

如升级后需要回滚：

1. 停止应用，备份当前 `db/main.db` 及 WAL 文件。
2. 恢复升级前的数据库备份。
3. 回退代码到上一版本。
4. 注意：新版本写入的 `unit`、`expiry_date` 字段在旧版本中会被忽略；旧版本不会主动删除这些列，但新版本生成的采购单/工单数据在旧版本中可能无法完整解析。
